/*
TEMPLATE for every record: inductions, preflights, QC checks, inspections. A page made from this
template gets the record tag instead of record-template, so this page never becomes a record
itself. The ~~META:title~~ line at the top only names this page in the sitemap; new pages don't
get it.

Nothing reaches the SPL Registry app until a page is approved. Press Preview to check a page before
saving: any problem, including a <placeholder> still in the header, shows in a box above the editor.
Version, Issued and Approved by fill themselves in when the page is approved; don't type over them.

1. Fill in the header (replace every <...>). Only ID and Type are required; put - in any row that
   doesn't apply.
   - ID: never change it once records exist. Inductions: IND_<building>_<room>_<EQUIPMENT or SPACE>.
     Checklists: CHK_<thing>_<purpose>, e.g. CHK_UAV_PREFLIGHT.
   - Type: how the app runs it.
       induction  an assessor runs it with one or more people, both sign, the person confirms by
                  email and gets a certificate. Records who is inducted on what.
       checklist  someone fills it in and submits it. Records what was checked, by whom, and when.
   - Category: any label you like. The app makes a filter for every category it sees, so a new
     one (e.g. "battery") just appears; nothing to set up.
   - Location, SWP, RA: as for SWPs. SWP and RA also let items attach their text (see References).
   - Requires: inductions a person must hold before doing this one (or submitting this checklist).
   - Grants access: inductions only. Comma separated; card readers use the id made from each name
     (j11-n209b), or write "id: Name" to fix it yourself.
   - Outcome: checklists only. Two results separated by /, e.g. Go / No-go, Pass / Fail,
     Airworthy / Grounded: the first when nothing failed, the second when any item failed. Or one
     word, e.g. Complete, for a checklist that just records that it was done. Left out (-): Pass / Fail
     if any item can fail, otherwise Complete.
   - Refresh (months): how long it stays current. Inductions: the default refresh period (the
     assessor can change it at sign-off). Checklists: when it is next due, e.g. 6 for a 6-monthly
     inspection. 0 = no expiry.
   - Self-service: yes if it can be done without an assessor.
   - Signature required: yes to make people sign. Inductions: the inductee draws a signature as well
     as typing their name. Checklists: whoever submits it signs at the bottom.
2. Write the one-paragraph description under the header.
3. Keep the checklist block you want (delete its first line, starting "/* ----------", and its END
   line), then delete the other blocks. Or write your own sections from scratch.

Items: every item is  [kind] text {options}
  Kinds
  * [ ] or [check]   covered and explained; ticked by the assessor (or the person, if self-service)
  * [demo]           demonstrated by the person; ticked by the assessor
  * [ack]            acknowledged by the person; ticked on their own phone
  (inductions use [ ], [demo] and [ack]; checklists use everything except [demo])
  * [pass]           Pass / Fail / N/A
  * [num MIN-MAX U]  a reading, e.g. [num 25.0-25.2 V]; outside the range counts as a fail
  * [select A|B|C]   pick one, e.g. [select Clear|Light rain|Windy!]; a choice ending in ! is a fail
  * [text]           a short answer
  * [rich]           a longer formatted answer (notes, flight log)
  * [photo]          a photo is the answer
  * text             information only, not ticked
  Options (any kind, as many as you like, after the text)
  {photo}            a photo can be attached
  {photo!}           a photo must be attached
  {comment}          a comment box
  {comment on fail}  a comment is required when the item fails
  {optional}         the item can be left blank

References attach SWP or RA text to an item. Link the page with a label that starts with intro,
hazard:, step, section:, risk: or emergency:, e.g. ([[whs:swp:swp-002|hazard: Burns]]).
*/
